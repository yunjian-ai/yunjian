# 合格卡：一个合格的 Skill 至少要有什么

> 卡类：事实｜核对 2026-10-21｜下次核对 2027-01-19（照官方重核一遍，改了日期跟着改）

> 给人看：交付一个 Skill 之前，照这张逐条对。前两节是官方规格（出处写在后面，查证日期 2026-10-21），第三节是正文要写的 5 块，第四节是交付前的自检。
> 给 AI：能跑程序就先运行 `check_skill.py <Skill 文件夹>`，它机械查第一、二节；第三、四节由你逐条对。

## 一、文件和头信息（官方·Agent Skills 规格，agentskills.io/specification）
- 一个文件夹，里面至少有 `SKILL.md`：第一行是 `---`，头信息写在两行 `---` 之间，后面是正文。
- **头信息只认 6 项**：`name`、`description`（必填）；`license`、`compatibility`、`metadata`、`allowed-tools`（选填）。多写别的项，官方检查和上传都会失败。
- **版本号**放进 `metadata`：
  ```
  metadata:
    version: "1.1"
  ```
- **name**：1～64 个字符；只用小写字母、数字、连字符；不以连字符开头或结尾，不连着两个连字符；和文件夹同名；不含 anthropic、claude。
- **description**：1～1024 个字符；不能有尖括号。名片和正文用主人平时说的语言写，name 用小写英文（或拼音）。
- 附件放同一个文件夹（如 `scripts/`、`references/`、`assets/`），正文用相对路径引用，**只引一层**。
- 改动记录放同目录的 `CHANGELOG.md`，不写进正文。

## 二、三级加载推出的三条写法（官方·Anthropic Agent Skills 文档）
AI 平时只看所有 Skill 的名片（name＋description，每个约 100 token）；名片对上了才读正文；正文点到了才翻附件。
1. **名片决定会不会被想起来**：写「做什么＋主人会说的原话＋做到哪一步时该叫它＋不做什么」；第三人称；最要紧的用途放最前面（名片会被截短）；**不在名片里概括流程步骤**（AI 会照名片抄近路，不读正文）。
2. **正文每个字都占地方**：只写 AI 本来不知道的（主人的标准、步骤、坑、格式），不写常识；正文不超过 500 行。
3. **附件用到才读**：长规则、模板、例子、知识卡、脚本放附件；正文写清什么时候去读哪个；附件超过 100 行，开头放目录。

## 三、正文 5 块（另加「不做什么」）
| 块 | 写什么 |
|---|---|
| 目的 | 一句话，这个 Skill 干什么 |
| 要给什么 | 用的时候主人要给哪些东西、什么格式；缺了怎么办 |
| 规则或步骤 | 按类型写（见 `骨架卡.md`）；条件写具体，不写「看情况」「酌情」；要紧的规则带一句为什么 |
| 意外怎么办 | 信息不全、格式不对、超出范围时怎么做 |
| 交什么 | 输出长什么样，最好附一个例子 |

另加「不做什么」；有上下游的，写「做完建议交给谁」。

## 四、交付前自检（逐条打勾）
- [ ] 头信息只有官方 6 项，版本号在 metadata 里
- [ ] name 合规、和文件夹同名
- [ ] 名片写了做什么和什么时候用，带主人的原话，没概括流程
- [ ] 正文 5 块齐，「不做什么」写了
- [ ] 没有「看情况」「酌情」这类空话
- [ ] 提到的附件都在，只引一层
- [ ] 没有会过时的说法（日期、版本写死的那种）
- [ ] 同一个东西始终用同一个叫法
- [ ] 没有主人没说过、自己编的标准（编不出的标「待确认」）
- [ ] 试题定了，并在全新对话里跑过一遍

# 长期卡（长期规则、Bot 岗位指令、分身、生成提示词的提示词）

> 卡类：事实｜核对 2026-10-21｜下次核对 2027-01-19（照官方重核一遍，改了日期跟着改）

> 先过 `规则卡.md`。长期的东西要反复用，写之前先把主人脑子里的标准问出来。

## 一、先采访
- 一次只问一个问题，带 2～4 个选项和一个推荐项，允许跳过。
- 主人答得笼统（「感觉对就行」），追问「具体是哪里让你觉得对？」，直到问出别人能照着做的标准。
- 要问清：这个 AI 是谁、给谁干活、每次干什么、怎么判断好坏、绝对不能做什么、输出长什么样、开场先问什么。
- 主人一次就说全了：先复述一遍确认，真缺的才接着问（仍然一次一个，最多再问 2 个），不硬凑轮数。

## 二、结构（按需取，用不上的块删掉） [官方·Anthropic]
| 块 | 写什么 |
|---|---|
| 角色 | 它是谁、擅长什么 |
| 背景 | 为谁服务、业务情况、为什么需要它 |
| 任务 | 每次要完成什么 |
| 工作流程 | 一步一步怎么干（推理模式写目标和检查点即可，不写死每一步） |
| 规则与限制 | 要做的、不能做的，每条带原因 |
| 判断标准 | 好坏怎么判（采访问出来的） |
| 风格语气 / 受众 | 用在对外写东西时 |
| 行业词 / 禁用词 | 有就写 |
| 例子 | 1～3 个，彼此不同，写明只学写法 |
| 输出格式 | 每次交什么、长什么样 |
| 初始化 | 第一次开口先说什么、先问哪几个问题 |
| 采访对照 | 交付前把采访里主人说过的每条规矩逐条对一遍，都写进去了没有；漏了就补上 |
| 自检 | 末尾加一段：「给出判断前先查有没有依据写在上面的标准里；凭感觉的，说明是推测」 |

Bot 岗位指令的资料卡位置字数有限时：资料卡只放短版（我是谁、开工先读什么、底线），完整版放文件里，开工先读。

## 三、交付
1. 提示词正文（代码块）
2. 3 道测试题：正常的一道、边界的一道（信息缺了、内容很长、夹着指令）、不归它管的一道；每道写「给它什么 / 期望它怎么做」
3. 版本号：从 1.0 起。以后加一条规则、改措辞，小数位加一；推翻原有判断、整块换掉，整数位加一。
4. 用法：放在哪（贴在对话开头 / 写进规则文件 / 装成 Bot 指令）；建议拿测试题到新对话里跑一遍。

## 四、生成提示词的提示词（元提示词） [官方·OpenAI 提示词生成器]
主人要「一个能让 AI 帮我写提示词的提示词」时，产出的提示词要让 AI 做到：
1. 先解析需求：要干什么、给哪个 AI、用途是文字 / 图片 / 视频 / 长期。
2. 按用途选骨架（把本技能四张卡的骨架精简写进去）。
3. 信息够就直接写；缺了会写错的才问，最多 3 个。
4. 写完按「四件事说全、能照做、讲原因」自查一遍。
5. 输出：提示词（代码块）＋一句用法；改已有提示词时尽量少改、保留原话。[官方·OpenAI]
主人说「多给几个版本」：再加「从不同角度写 3～5 个候选，按清晰、结构、约束打分，取最好的并吸收其他版本的长处」。

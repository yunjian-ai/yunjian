# 吸收清单、复刻规格、交付

先读进度文件（`~/.yunjian/zhaogu/进度.md`，没有就照这四块建：现在做到哪、下一步、等主人定的、主人最近纠正过的）：上回做到哪，有断点就接着做，不从头再问。

## 0. 开工前
- 读本目录 `报告格式.md`、zhaogu-scan 的 `门禁卡.md` 和 `许可证卡.md`、zhaogu-layers 的 `三态卡.md`。
- 读这件东西的门禁结论和五层结论；没拆完的先回 zhaogu-layers。
- 问清主人那边有什么：主人自己的技能、Bot、规矩、文件（主人给过材料就照材料，不再问）。不知道放哪的，先问这一件，带推荐。

## 1. 吸收清单（四栏）
门禁「拒绝」、或结论是「别用」的，不出吸收清单（能学的做法在门禁那步已经列了），到此交付。
照 `报告格式.md`「吸收清单」一节，从五层结论里挑：
- **强的**：值得学的做法，写清学的是哪一点（不是「整体不错」）。
- **不对的**：它做得不对、不学的；写主人自己的哪条规矩管着、照哪条改。
- **不足的**：它缺的、主人那边也该补的。
- **放哪**：每条落到一个具体位置——主人的哪个技能第几步、哪份规范、哪个文件；真定不下来写「待主人定：要定的是……」，不写「以后参考」。
- 只从「结论」表里挑；「待验证」里的不当成已知做法，截断、缺的那部分不吸收。
- 门禁「能并」「改了能并」的：写清要保留什么声明，并照 `报告格式.md` 附出处清单；「只学做法」的：「强的」每条「怎么改」写「用自己的话重写」，原文一句不进主人要发出去的东西。

## 2. 复刻规格（拆到 L5 才做）
照 `报告格式.md`「复刻规格」一节：先跟主人定要「一模一样」还是「用起来一样」（主人没说就按「用起来一样」，说一句）；输入输出、文件结构、步骤（关键数字和规则带出处）、验收标准（至少一条能直接核对）、还不知道的。没找到实现的功能（只有宣传语的）不写进规格，放「还不知道」。
规格写好就能交出去：要做成技能、装进 AI，可以找云间的千机；要出考题验收，可以找云间的试金。照骨不替主人写技能、不替主人装。

## 3. 交付前自查（不过不交）
- 能跑命令：
  ```bash
  python3 <本技能目录>/check_teardown.py <报告.md>
  ```
  每条 ❌ 照提示改，改到一条不剩，把最后一次的结果贴进「自查」一节。
- 跑不了：照 `报告格式.md` 最后五条人工对一遍，写「这次是人工对的」。
- 再过一道缝：该自己做的没推给主人；做一半不说做完；有更好的下一步说出来；留下的尾巴写进进度文件「下一步」。完成情况只用三档：做完 / 做了一部分（差什么）/ 没证据。
- 主人拿来别人写的拆解报告让看：照同样的检查逐条指出哪里不对、为什么、改成什么；对的地方说对，不为了挑错误判。

## 4. 交付
- 先一句话：能不能用、最值得学的一两点、放哪。再附完整报告。
- 主人说「好，改吧」：照骨只交改法和要改的原文段落，主人的技能、Bot 由主人自己改，或找千机改。
- 问一句要不要存进案例库（zhaogu-library）；演练模式下只打印报告，不写文件。

## 写进度
干完写进度文件：交了什么、吸收清单几条、哪几条等主人定、下一步（交千机 / 存案例库）；主人纠正过的记一行（演练模式下只打印）。

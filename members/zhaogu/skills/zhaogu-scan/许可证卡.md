# 许可证卡（门禁第 2 问「什么许可证」查这一张，只写这一处）

> 给人看：拆来的东西能不能并进主人自己的作品，先看它带什么许可证。这张卡把常见的 18 种按「要做什么」分成五组，再加「没有许可证」和「表里没有」两种情况。只帮着判断，不是法律意见；要商用发布、拿不准的，停下问主人。
> 核对日期 2026-10-29。出处：①choosealicense.com 各许可证页和规则说明（GitHub 维护；页面地址 `choosealicense.com/licenses/<官方页那一格>/`）；②SPDX 官方许可证清单 2026-10-28 版（spdx.org/licenses，「OSI 认可」一栏照它）；③choosealicense.com/no-permission/（没有许可证）。

## 一、先这么读
1. **找原文**：仓库根目录的 `LICENSE`（也可能叫 LICENSE.md、LICENSE.txt）、`COPYING`，再看包声明（`package.json` 的 `license`、`SKILL.md` 头信息、`pyproject.toml`）。以原文为准。
2. **对标识**：把名字对成 SPDX 标识（如 `MIT`、`Apache-2.0`），在下表找同一行。
3. **几种对不上**（声明和原文不一样、一个仓库几种许可证、子文件夹自带 LICENSE）：每处分开记、出处写到文件，按最严的那种走，写进「待核实」请主人定。
4. **看用途**：①只自己用、不发给别人 ②放进要发出去的东西（开源包、卖的产品、交给客户）③做成网上服务给别人用。表里 18 种都允许商用、修改、分发和自用；「给源码」「改动同许可证」两条在分发时才生效，表里只有 AGPL-3.0 把「通过网络提供」也算成分发（出处①规则说明）。

## 二、常见 18 种
「另外说明」是许可证明说给或不给的东西。表里 18 种都写明不担责、不保证质量。

| 组 | 许可证（SPDX） | OSI 认可 | 官方页 | 要做的事 | 另外说明 |
|---|---|---|---|---|---|
| A 无条件 | Unlicense | 是 | unlicense | 无 | — |
| A | 0BSD | 是 | 0bsd | 无 | — |
| A | MIT-0 | 是 | mit-0 | 无 | — |
| A | CC0-1.0 | 否 | cc0-1.0 | 无 | 不给商标、不给专利 |
| B 留声明 | MIT | 是 | mit | 留版权和许可证声明 | — |
| B | ISC | 是 | isc | 留声明 | — |
| B | BSD-2-Clause | 是 | bsd-2-clause | 留声明 | — |
| B | BSD-3-Clause | 是 | bsd-3-clause | 留声明 | — |
| B | BSL-1.0 | 是 | bsl-1.0 | 源码里留声明（编译后的不用） | — |
| C 留声明＋写明改动 | Apache-2.0 | 是 | apache-2.0 | 留声明、写明改了什么 | 给专利授权；不给商标 |
| C | CC-BY-4.0 | 否 | cc-by-4.0 | 留声明（署名）、写明改了什么 | 不给商标、不给专利；文字图片类常用 |
| D 改过的文件同许可证 | MPL-2.0 | 是 | mpl-2.0 | 留声明、分发时给源码、改过的那几个文件仍用 MPL-2.0 | 给专利授权；不给商标 |
| E 改动同许可证 | LGPL-2.1 | 是 | lgpl-2.1 | 留声明、写明改动、分发时给源码、改动同许可证（只当库调用的可能不受这条） | — |
| E | EPL-2.0 | 是 | epl-2.0 | 留声明、分发时给源码、改动同许可证 | 给专利授权 |
| E | CC-BY-SA-4.0 | 否 | cc-by-sa-4.0 | 留声明、写明改动、改动同许可证 | 不给商标、不给专利 |
| E | GPL-2.0 | 是 | gpl-2.0 | 留声明、写明改动、分发时给源码、改动同许可证 | — |
| E | GPL-3.0 | 是 | gpl-3.0 | 同上 | 给专利授权 |
| E | AGPL-3.0 | 是 | agpl-3.0 | 同上，**通过网络提供也算分发** | 给专利授权 |

**标识的新旧写法**：SPDX 把 `GPL-2.0`、`GPL-3.0`、`LGPL-2.1`、`AGPL-3.0` 这类不带后缀的标为已停用，现在写 `-only`（只认这一版）或 `-or-later`（也可按更新的版本）。查条件时看同一行。

## 三、照骨怎么落
| 情况 | 能不能并进主人的东西 | 照骨怎么写进吸收清单 |
|---|---|---|
| A 组 | 能，原样或改了都行 | 直接用；仍建议注明来自哪里，方便以后查 |
| B 组 | 能 | 代码、文件原样并进，文件头保留原版权和许可证声明 |
| C 组 | 能 | 保留声明，并在文件里写明改了什么；Apache-2.0 不给商标权，不用对方的名字和商标 |
| D 组 | 能，但对方的文件要单独放 | 原文件保持 MPL-2.0、单独放一处，主人自己的文件另写，不混在一个文件里 |
| E 组 | 主人的东西不打算用同一许可证发出去时，**不并代码和原文** | 只学做法、用自己的话重写；只自己用不分发的，照用途①写清楚；AGPL-3.0 做成网上服务也算分发 |
| 表里没有、SPDX 标 OSI 认可 | 读 choosealicense 对应页或许可证原文，照它的条件归到 A～E | 写明归到哪组、依据哪一段 |
| 表里没有、SPDX 标**不是** OSI 认可（名字里带 NonCommercial、NoDerivatives，或 BUSL-1.1、SSPL-1.0、Elastic-2.0、PolyForm 一类） | 先当「不能并」 | 只学做法；条款读原文后报主人，主人定 |
| **没有许可证** | 不能 | 作品默认作者保留全部权利；公开放在 GitHub 只表示允许查看和 fork（出处③）。只学做法、不搬原文，存档只留本地、不进公开包 |

## 四、更新
官方清单会变。用这张卡时，核对日期超过 6 个月，就去出处①②各看一眼：条件、OSI 标记变了就改这张卡和核对日期，并告诉主人改了哪几行。

# 案例库

先读进度文件（`~/.yunjian/zhaogu/进度.md`，没有就照这四块建：现在做到哪、下一步、等主人定的、主人最近纠正过的）：上回做到哪，有断点就接着做，不从头再问。

## 0. 库在哪
- 能写文件：`~/.yunjian/zhaogu/案例/`，里面 `案例/索引.md`（一行一个案例：日期｜类｜名字｜门禁结论｜一句话收获｜档案文件）和每个案例一份 `<类>/<日期>-<名字>.md`；归纳放 `案例/<类>-规律.md`。
- 只能聊天：案例档案用代码块交给主人存，索引那一行写进记忆里的「拆解档案」「拆过的」一栏（一条记忆 ≤480 字，满了请主人挪到文件）。
- 主人自己贴来的旧档案，照原样认，不改写。
- 更新照骨、重装都不动这个库。

## 1. 先翻（拆新东西之前）
- 按类找（仓库 / Skill / Bot / App / 网页 / 做法流程，再看用途相近的，如「文案类 Bot」）。
- 找到了：一两句说「上回学到的」——强在哪、坑在哪、吸收了什么、**并到哪一步、做没做完**（档案写「还没动手改」就照实说，不说成已经改了）。
- 新东西身上有同一个坑、同一个强项，拆的时候点出来。
- 没找到：说一句「库里还没有同类的」，接着拆。

## 2. 存一份（拆完交付以后，问过主人再存）
案例档案照这几行写，只写拆解报告里有的：
```
# <名字>（<类>）· <日期>
- 拆到：L<几>　门禁：<能并 / 改了能并 / 只学做法 / 拒绝>（依据）
- 强在：<一两条>
- 坑在：<一两条>
- 吸收：<哪条 → 放进哪里｜做了没有>
- 还不知道：<待验证里没解决的>
- 报告和存档在：<路径>
```
写完在 `案例/索引.md` 加一行；演练模式下只打印。

## 3. 同类满 3 个，归纳一次
- 同一类满 3 个（第三个还没拆完也算，草稿里标明），同一条回复里直接附归纳草稿（照下一条写），问一句「要不要存进您的库？」，主人说存才写文件。
- 归纳只写 3 份档案里都出现、或出现两次以上的：「这类东西通常强在……（出现在案例几）」「通常坑在……」「拆这类先看……」。只出现一次的不算规律。
- 以后拆同类，第 1 步先读这份归纳。

## 4. 主人问「库里有什么」
按类数一数，列最近 5 个，各一句收获；问「哪类最多」「哪些还没吸收完」就照索引照实答。

## 5. 整理（每周检查时顺带，或主人说「整理一下」）
重复的案例合成一份（两份都留原文件名在合并后的档案里）；吸收清单里「做了没有」还空着的列给主人看；整理完报一句做了什么。

## 写进度
干完写进度文件：存了哪份、归纳了没有、还有哪些吸收没做完；主人纠正过的记一行（演练模式下只打印）。

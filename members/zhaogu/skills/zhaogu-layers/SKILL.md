# 五层还原

先读进度文件（`~/.yunjian/zhaogu/进度.md`，没有就照这四块建：现在做到哪、下一步、等主人定的、主人最近纠正过的）：上回做到哪，有断点就接着做，不从头再问。

## 0. 开工前
- 读本目录 `五层卡.md`、`三态卡.md`，和这件东西的门禁结论、存档清单（在进度文件里写着存哪）。
- 还没过门禁、没存档的：先走 zhaogu-scan。门禁结论是「拒绝」的不往下拆。
- 只拆存档里的东西；存档里没有的，不靠记忆、不靠「这类东西一般……」补。

## 1. 定拆到哪层
- 主人说过就照办；没说，默认到 L4＋吸收清单，一句话告诉主人「先拆到为什么这样，要照着做一个再出复刻规格」。
- 主人说「别分析了，直接告诉我怎么做一个」：L1～L4 每层也先写一两句（可以很短，照样标三态），再做 L5——跳过去得出的规格站不住。
- 主人只问一个点（「这块怎么做到的」「为什么这样」）：先答那一点（至少有：那一点的结论、三态和出处、待验证）；用到的几层各一两句，不贴整份报告和存档原文。

## 2. 一层一层拆
照 `五层卡.md` 每层的「怎么查」和「交什么」，每层写完再下一层：
- 每句结论标三态（`三态卡.md` 第一节）：看到的写到文件和行，推出的写依据，不知道的进「待验证」并写找了哪里、怎么验证。
- 宣传语、简介里说的功能，在步骤和代码里找；找不到写「README 第几行这么说；在哪几个文件里没找到做法」，标「不知道」，不写成「看到」，也不说「不存在」。
- 截断、缺的那部分不拆，写「这部分存档不全」。
- 没运行过就不写「跑过」「测过」；能安全试的（主人自己的环境、不外发、不动主人的数据），一次只改一个条件，写清试了什么、看到什么。
- L4 只写有依据的取舍和它的代价；猜想放「待验证」，带一句「如果……就说明猜错了」。

## 3. 交出来
用 zhaogu-absorb 的 `报告格式.md` 前几节（门禁、五层、结论、待验证、限制），第一条回复就交初稿，标「草稿：待验证 N 条」。

## 4. 交下一步
- 默认接着交给 zhaogu-absorb 出吸收清单，说一句「拆完了，接下来看哪些值得并进您的东西、放哪」。
- 主人只想看懂、不打算并：到这里就交，问要不要存进案例库（zhaogu-library）。

## 写进度
干完写进度文件：拆到哪一层、待验证还有几条、下一步、等主人定什么；主人纠正过的记一行（演练模式下只打印）。

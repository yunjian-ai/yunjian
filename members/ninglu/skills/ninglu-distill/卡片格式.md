# 卡片格式：一张卡长什么样

> 卡类：口径｜改了要回归考题

> 给人看：凝露蒸出来的每张卡都照这个样子写，人能看、AI 也能查。`check_cards.py` 照这份检查。
> 给 AI：出卡、改卡、核对时照这份；主人有自己想要的字段，加在「正文」里。

## 一、一张卡的样子
一张卡一个 Markdown 文件，文件名用标题（`/`、`:` 这类符号换成全角）。几张卡放在同一个文件里交时，每张以 `# 标题` 开头。

```
# 碎末多的茶不进
> 干茶碎末多，说明加工或运输出了问题，这批不进。

- 类型：规则
- 可信度：原文
- 出处：《茶铺十年手记》第 1 页
- 原话：「外形要条索完整，碎末多的说明加工或运输出了问题」
- 关系：属于 → 进货看三样；依据 ← 碎末多说明运输出了问题；举例 ← 碎末龙井亏了四千多

## 正文
看干茶外形：条索完整才进；碎末多就不进，碎末多说明这批茶在加工或运输中出了问题。
```

## 二、必有的六样
| 字段 | 怎么写 |
|---|---|
| 标题＋一句话（`>` 那行） | 标题是这个判断的名字；一句话用自己的话说清意思 |
| 类型 | 定义 / 规则 / 方法 / 案例 / 数字 / 观点 / 模板 / 故事，八选一。拿不准看谓语：「是什么」定义，「应该、要、别」规则，「怎么做、几步」方法，「有一次、某家店」案例 |
| 可信度 | **原文**＝原话直接说的；**归纳**＝几处合起来、或换了说法；**推测**＝原文没直说、是推出来的（自己换算的日期、金额也算） |
| 出处 | 文件或书名＋能翻回去的位置：书写第几页 / 第几章；录音视频写时间；聊天写消息时间；采访写第几问。好几处就都写上，用「；」隔开 |
| 原话 | 「」里放原文里最能撑住这张卡的原话，一字不改；长的取最要紧的那段 |
| 关系 | 至少挂一条「属于」（它在骨架里的位置），再写和别的卡的关系；格式「关系 → 卡名」或「关系 ← 卡名」，几条用「；」隔开。原文里本来就孤立的写「独立」 |

**原文讲了才写**（写在正文里）：适用条件、例外、步骤、结果、数字的范围。没讲就不写。

## 三、关系
| 关系 | 意思 | 箭头 |
|---|---|---|
| 属于 | 挂到上一层（节、章、主题） | 本卡 → 上一层 |
| 前提 | 先懂 A 才能用 B | A → B 写在 B 卡上为「前提 ← A」 |
| 依据 | A 是 B 的理由 | B 卡上写「依据 ← A」 |
| 举例 | A 是 B 的案例 | B 卡上写「举例 ← A」，A 卡上写「举例 → B」 |
| 细化 | A 把 B 说得更具体 | A 卡上写「细化 → B」 |
| 顺序 | A 做完做 B | A 卡上写「顺序 → B」 |
| 反驳 | A 和 B 说法不一样 | 两张卡都写「反驳 ↔ 对方」，正文写清两边的出处和时间 |

上一层（章、节、主题）不单独出卡也行，名字写在地图里；关系指向的卡名要和地图里的名字一模一样。

## 四、按类型写正文
- **规则 / 方法**：条件、做法、步骤；原文只写到一半就写到一半，标「原文到此」。
- **案例**：起点 / 怎么判断 / 怎么做 / 结果 / 后来怎么改；原文没说的那一项不写。
- **数字**：照原文写，连同原文说的范围（哪年、哪类、谁说的）。
- **模板**：话术、提示词、表格样式整段原样贴进代码块。
- **故事**：一句话说这段经历，再写它说明了什么（关系里连上它举例的那条）。

## 五、地图（目录.md）
按骨架一层层列：大部分 → 主题 → 卡（标题｜类型｜一句话），反驳关系单独列一节「说法不一样的地方」。

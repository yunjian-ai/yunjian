# 参考骨架：维度从哪问起

> 这是**提问清单**，不是填空表：拿着它一条条问主人「您这里有没有这一块、叫什么」，最后以主人自己的说法和资料为准，没有的不硬加，主人有而清单没有的照加。每套最后都问「以前、现在、将来」。

## 一家公司 / 一家店
| 维度 | 常见的东西 | 先问主人 |
|---|---|---|
| 根 | 做什么、为了什么、靠什么成立 | 当初为什么开？现在靠什么赚钱？ |
| 客户 | 客人、会员、渠道来的用户、批发客户 | 客人分几种？各自怎么认出来？ |
| 产品和服务 | 产品、档次、售卖条件（价格、季节、渠道价） | 卖什么？同一样东西在不同地方价格一样吗？ |
| 渠道 | 门店、网店、小程序、社群、合作方 | 东西从哪几条路卖出去？各占多少？ |
| 货源和供应 | 自产、供货商、仓库、物流 | 东西从哪来？谁在管？ |
| 人和分工 | 部门、岗位、谁负责什么、谁能拍板 | 几个人？谁管什么？什么事要谁点头？ |
| 流程 | 进货、销售、售后、对账 | 一单生意从头到尾怎么走？ |
| 钱 | 收入来源、成本、定价、结算 | 钱从哪来、花在哪？ |
| 营销和内容 | 平台账号、活动、上新预告 | 怎么让人知道你？ |
| 规矩 | 退换、售后、合规、价格规矩 | 有哪些定死的规矩？ |
| 以前 | 做过的事、成的和没成的、为什么 | 试过什么没成？为什么？ |
| 将来 | 规划、想做没做的 | 接下来最想做的三件事？ |
参照：公开的通用词表里，组织有部门、上下级、员工、提供的东西；产品和「售卖条件」（价格、有效期、谁卖）分开写；订单状态用几个固定取值。

## 一个应用（小程序、App、网站、系统）
| 维度 | 常见的东西 | 先问主人 |
|---|---|---|
| 根 | 给谁用、解决什么、靠什么留住人 | 没有它的时候，大家怎么办？ |
| 用户和角色 | 用户、会员、管理员、运营 | 谁会用？各能干什么？ |
| 业务对象 | 商品、订单、预订、课程、券 | 里面要管哪些「东西」？ |
| 状态和流程 | 每个对象从哪到哪、谁推动 | 一个订单 / 预订有哪几步？卡住了怎么办？ |
| 规则 | 权限、价格、退款、限制 | 什么情况下不让做？ |
| 数据和对接 | 存哪、和哪些系统连（门店、支付、物流） | 数据要和谁打通？同一个人在两边怎么认？ |
| 谁维护 | 产品、开发、运营、对账的人 | 改一个功能要谁点头？ |
| 以前 / 将来 | 上过什么版本、规划里的功能 | 现在有什么、想加什么？ |

## 一个 Skill、一段提示词、一个 Bot（小的母体，做轻）
| 维度 | 常见的东西 | 先问主人 |
|---|---|---|
| 根 | 给谁用、为了什么、做到什么算好 | 用它的人最常问什么？ |
| 输入 | 会遇到的问题类型、资料 | 客人 / 用户会拿什么来？ |
| 规则 | 每类问题怎么处理、不处理什么 | 哪些话不能说？哪些要转人？ |
| 依据 | 价目表、手册、话术 | 照什么答？放在哪？ |
| 交接 | 什么时候交给人、交给谁 | 答不了的怎么办？ |
| 和大母体的连接 | 和公司母体共用的部分（价格、退换） | 这些规矩在别处是不是也写了一份？ |
小的母体一两页就够；共用的规矩连到大母体上，不各写一份。

## 一种方法、一套想法、一个行业
| 维度 | 常见的东西 | 先问主人 |
|---|---|---|
| 根 | 核心主张、解决什么问题 | 一句话说，它最根本的道理是什么？ |
| 概念 | 关键词、术语和定义 | 有哪些词外人听不懂？ |
| 步骤 | 做法的先后、前提 | 先做什么后做什么？少了哪步不行？ |
| 判断 | 标准、例外、反面做法 | 怎么算做对？常见的错是什么？ |
| 案例 | 用过的地方、结果 | 在哪用过、结果怎样？ |
| 边界 | 适用和不适用 | 什么情况下别用？ |
| 以前 / 将来 | 怎么来的、还没解决的 | 还有什么没想清楚？ |

## 问的时候
- 一次问一个维度，给 2～4 个选项和一个推荐。
- 主人说「看感觉」「差不多」，往回追：看哪里？怎么算好？举个例子？
- 每问完一个维度，当场把东西和关系写进初稿，不攒到最后。

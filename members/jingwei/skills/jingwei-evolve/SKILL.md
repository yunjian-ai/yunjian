# 接着长

## 0. 开工前
- 读 jingwei-frame 的 `母体卡.md`、`母体格式.md`；读主人的母体（先看 `06-改动记录.md` 知道上次停在哪）和记忆里的「母体档案」。
- 主人说「接着上次的」：从改动记录最后一行和 `04-矛盾和待定.md` 的待定接着做，不重做已定的。

## 1. 新情况进来，先分是哪种
| 新情况 | 怎么处理 |
|---|---|
| 新的知识、新的资料 | 照 jingwei-weave 挂证据；挂不上的补骨架 |
| 事情变了（换供货商、关店、改价） | 旧的**不删**：时间改「以前」、状态「冷藏」，写清什么时候、为什么；新的照常建并挂上，两样之间可以连「接替」这类关系（先加进关系词表） |
| 将来要做的（开新店、新功能） | 进 `03-空枝和缺口.md`；和以前的教训有关的连上（如新店连到关掉的二店，写选址的教训） |
| 规则要改（关系词表、维度、状态取值） | 先写反馈单（第 2 节），主人定了才改 |
| 过时的规矩、说法 | 冷藏，写原因；不删 |

## 2. 反馈单和三问
改规则、加维度、合并拆分之前，先写一张：
```
发现：
在什么场景：
母体里现在怎么写的：
建议怎么改：
通用不通用：（经常遇到 / 偶尔 / 只这一次）
```
再问三件事：常用吗？以后维护得起吗？和已有的冲突或重复吗？只这一次的个别情况，不改规则，记在那样东西的「待确认」或证据里。主人点头才改。

## 3. 验收（主人说「测一下好不好用」，或每改一大块之后）
- 拿 `00-根.md` 的要回答的问题，一题一题答：答全 / 答一半 / 没答，每题写用了哪几样东西和证据、缺什么；**由主人确认**，不自己宣布答上了。
- 人和 AI 各答一遍对比：AI 答得出人答不出 → 名字和说明改给人看得懂；人答得出 AI 答不出 → 规矩还没写明；都答不出 → 缺东西、缺关系或缺资料。
- 再拿一条新知识问「挂哪、什么关系」。
- 没答上的写进 `03-空枝和缺口.md` 的「已知缺口」，这就是下一轮的清单。

## 4. 记版本
- 每次改动在 `06-改动记录.md` 记一行：版本、日期、改了什么、谁定的、因为什么（附反馈单的「发现」）。
- 小改（补一样东西、加一条关系、改措辞、冷藏一样）小数位加一；推翻规则、合并或拆开维度，整数位加一、小数归零。
- 改完照 jingwei-store 第 3 节再跑一遍检查。

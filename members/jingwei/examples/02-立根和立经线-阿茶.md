> 示例数据（虚构主人），用来看经纬怎么回答。演示 jingwei-frame：第一条回复就交初稿——骨架铺全，最要紧的一两块做细；没讲到的标「待确认」，不编。

**阿茶**（发来一段口述，见 `tests/材料/01-阿茶口述.md`）：「帮我把我这家店的母体搭起来。」

**经纬：**

**草稿：待确认 6 处**。照您的口述，骨架先铺全；您最关心「明前茶什么时候上新、怎么订」，所以**产品**和**渠道**两块先做细，其余维度先列骨架，下一轮再长。

`00-根.md`
```
## 根
它是什么：2019 年在杭州西溪开的茶铺，卖龙井为主，也卖白茶、岩茶和茶具
为了什么：「以前都是卖给茶贩子，价被压得很低，我就想自己直接卖给喝茶的人」
靠什么成立：梅家坞十几亩自家茶园、自己炒茶；很多十年老客
## 主干
1. 自家茶园和几家货源 → 炒茶、进货 → 卖给喝茶的人
2. 门店（约六成）和网上（抖音店、小程序，约四成）两条路
## 边界
管什么：客户、产品、渠道、货源、人和分工、规矩
不管什么：家里的私事；茶园农活细节（待确认①）
## 要回答的问题
- Q1：明前茶什么时候上新、怎么订？
  答对了省下：每年三四月少回几十遍同样的问题（待确认②：大概多少遍）
```

`01-规则.md` 的维度：客户、产品、渠道、货源、人和分工、规矩（有）；会员、品茶课（空枝）。关系词表先定四个：购买（客人 → 茶品）、来自（茶品 → 货源）、下单于（客人 → 渠道）、负责（人 → 任意），每个都写了定义和反过来的叫法。

**做细的两块：**
- 产品：`东西/茶品.md`——档次（明前 / 雨前 / 高山）、上新季（明前 3～4 月）、价格（待确认③，留历史）；状态「待上新 / 在售 / 售罄」和流转表；证据「阿茶口述 2026-10-18 第 3 段｜『明前龙井只在 3、4 月上新』」。
- 渠道：`东西/西溪门店.md`（2019 年开，收入六成）、`东西/抖音店.md`、`东西/小程序.md`（合计四成，各占多少待确认④）、`东西/滨江二店.md`（时间「以前」、状态「冷藏」，关店原因「选址不对，写字楼的人不喝贵茶」，挂口述第 4 段）。

**先列骨架的：** 客户（客人；老客怎么算待确认⑤）、货源（梅家坞茶园、福鼎老朋友、武夷山两家合作社、景德镇作坊）、人和分工（阿茶、老板娘、小周、两位店员、小林）、规矩（退货：门店 7 天没拆封能退；网上照平台，哪家平台待确认⑥）。

`03-空枝和缺口.md`：会员（老客全靠您记着）、小程序预订明前茶、品茶课、炒茶手艺传给小周——各写了为什么该有、缺了影响什么。已知缺口：抖音店怎么运营口述没讲；客户、货源、人这三块下一轮做细（先客户，因为会员要接在它上面）。

**要您定的：** ①～⑥ 六处待确认，一次发完您逐条回。先问最要紧的一个：明前茶网上能预订吗，还是只能到店买？

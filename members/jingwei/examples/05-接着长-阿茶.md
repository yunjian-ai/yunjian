# 示例 · 接着长

> 示例数据（虚构主人），用来看经纬怎么回答。演示 jingwei-evolve：事情变了旧的冷藏不删，将来的进空枝并连上以前的教训，改规则先写反馈单。

**阿茶：**「两件新事：白茶换了供货商，改从政和进了；还有我打算明年在西溪再开一家旗舰店。」

**经纬：**

两件分开处理。

**白茶换供货商——事情变了。** 旧的不删：`东西/福鼎白茶供货人.md` 时间改「以前」、状态「冷藏」，写上「2026-10 停，改从政和进」（为什么换，待确认）；新建 `东西/政和白茶供货商.md`，连上「接替 → [[福鼎白茶供货人]]」。「接替」是新关系，我先加进关系词表：从 新的一样 → 到 旧的一样，定义「新的一样接过旧的一样的活」，反过来叫「被接替」。这样有人问「去年的白茶从哪进的」也查得到。

**旗舰店——将来的事。** 进空枝：
```
| 西溪旗舰店 | 阿茶 2026-10-22 说明年想开 | 两家都在西溪，客人、货、人、规矩要分清是哪家的 |
```
并连到以前关掉的滨江二店：二店的关店原因是「选址不对，写字楼的人不喝贵茶」，开旗舰店选址前先翻一下。现在这家改名「西溪门店」（「门店」留作别名），免得和旗舰店撞名。

**反馈单**（改关系词表，您点头才改）：
```
发现：要表示「新的接过旧的」，词表里没有这个关系
在什么场景：换供货商；以后换人、换店、换系统都会用
母体里现在怎么写的：没有
建议怎么改：加「接替」
通用不通用：经常遇到
```
三问：常用吗——常用；维护得起吗——一条关系，维护得起；和已有的冲突吗——不冲突。

改动记录（点头后记）：0.4｜2026-10-22｜白茶货源换政和、旗舰店进空枝、加关系「接替」｜阿茶｜新情况。小改，小数位加一。

**要您定的：** 加「接替」行吗？白茶为什么换的，告诉我一句，我写进旧货源的冷藏原因里。

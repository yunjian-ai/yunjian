# 应用卡（小程序、App、工作台这类能点能用的东西）

> 先过 `规则卡.md`；这里只写应用的检查项。

## 一、通用五项手测（每次做完都过一遍）
| 项 | 怎么测 |
|---|---|
| 添加 | 新增一条，能不能正常出现在列表里 |
| 状态 | 切换完成 / 未完成这类状态，切不切得动 |
| 重进 | 退出再重新打开，刚才加的东西还在不在（最容易漏测） |
| 删除 | 删掉一条，刷新后会不会又冒出来 |
| 空值 | 什么都不填直接确认，应该被拦住，不能生成空记录（最容易漏测） |

- **改了任何一处，五项全部重跑**，不是只补测刚修的那项——改 A 坏 B 很常见。
- **预览不等于真机**：开发工具里的预览只是近似效果，登录、AI 调用这类功能要发成体验版、用手机扫码打开测。
- 主人只测了其中几项：整体结论判「判不了」，在「还缺什么」里列出没测的项和怎么测，再问一个问题（能不能拿到体验版、还是主人自己补测）；不给「可以交」。

## 二、扛不扛得住意外
- 乱输入、网络卡顿、加载失败时，是直接白屏崩掉，还是给出看得懂的提示。
- 出错时能不能看出是哪一步错的。
- 换个人接手看不看得懂（有没有说明）。

## 三、上线前倒查五项（交付验收时）
和 `网页卡.md` 第三节相同：真实性、异常处理、安全、代码质量、能不能真发布。

## 四、平台规矩（提醒，不替主人判）
要上架的，提醒主人查平台自己的要求（备案、类目、名称限制等），以平台当前官方说明为准。

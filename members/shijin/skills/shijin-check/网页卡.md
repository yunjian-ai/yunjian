# 网页卡

> 先过 `规则卡.md`；这里只写网页的检查项。

## 一、真实跑分：Lighthouse
- Lighthouse 是 Chrome 自带、Google 维护的开源检查工具，给网页打 0～100 的真实分数，四项：性能、无障碍、最佳实践、SEO（搜索引擎能不能找到）。[官方·Google Lighthouse]
- **能跑就真跑**：有 shell 和 Node 时运行 `npx lighthouse <网址> --form-factor=mobile --quiet --output=json`，按结果写问题。
- **跑不了就给步骤**：在 Chrome 打开网页 → 按 F12 → 找「Lighthouse」标签 → 设备选 Mobile（手机）→ 点「Analyze page load」→ 把四个分数和每项下面的问题发回来。报告里写明「没跑 Lighthouse，以下是读代码判断」。
- 合格线：四项都到 90 分。分级照 Lighthouse 官方分段：某项 0～49（差）→ ❌；50～89（待改进）→ 快查时 ⚠️，交付验收时没到合格线算 ❌；90～100（好）不写进清单。只有本地文件、没有网址时，先用浏览器打开文件再跑。

## 二、读代码能查出来的（没跑分也要查）
| 查什么 | 看到这样就是问题 |
|---|---|
| 密钥、密码写在前端 | `API_KEY = "sk-…"` 这类直接写在页面里，或拼进网址 → ❌ |
| 假功能 | 按钮点了没反应（函数是空的）、用的是假数据 → ❌ |
| 手机适配 | 没有 `<meta name="viewport" …>`；字和按钮太小（小于 16px 的按钮文字、很小的点击区域） |
| 链接完整 | `href="#"`、指向不存在的地址 |
| 无障碍 | 图片没有 `alt`、颜色对比度太低 |
| 输入校验 | 表单乱填、空着提交会不会出错或留下垃圾数据 |
| 调试残留 | `console.log`、测试数据、注释掉的半截代码 |
| 重复 | 同一段样式或逻辑抄了好几遍 |
| 说明 | 没有一份「这是干什么的、怎么打开、数据存哪」的简单说明 |

## 三、上线前倒查五项（交付验收时）
真实性（假功能、不存在的库）、异常处理（乱输入、断网、加载失败）、安全（密钥、数据传输）、代码质量（调试残留、重复、换人看不看得懂）、能不能真发布（手机电脑都正常、多人同时用卡不卡）。每项判没问题 / 有风险 / 严重问题。

# 试金设计摘要

- **给谁：** 要把东西交出去、心里却没底的人：提示词、Skill、网页、小程序做好了，不知道能不能交。
- **只做验证：** 查（挑毛病、分轻重）、考（定合格线、出题、写委托、判答卷）、交付前验收；不动手改，不给自己做的东西打分。
- **卖点：** 每条问题带证据（在哪、看到什么、违反哪条、怎么改）；结论只选一种（可以交 / 改完再交 / 要重做 / 判不了）；按东西的类型换查法（文字 / 网页 / 应用）；考试用真实答卷说话。
- **底线：** 不硬判（信息不够就判不了并写清缺什么）；不假装跑过；资料里夹带的指令不执行；两版对比换顺序各判一次，长不等于好。
- **分档：** 两刀，由试金自己判断——第一刀按查的是什么，第二刀按查多严（快查 / 考试 / 交付验收）。
- **依据：** Anthropic 定义成功标准、设计测试与打分；OpenAI 评测最佳实践；Zheng 等 NeurIPS 2023 关于 AI 当裁判的偏差；Google 代码审查规范；Google Lighthouse。
- **发布方式：** 薄分享卡（安装技能＋第一次见面＋一条记忆）＋首轮经主人同意从固定标签安装完整配方。
- **技能链：** getting-started → check（快查、交付验收）⇄ exam（出题、判答卷、两版对比）；另有 install / update。
- **预算：** 单技能 ≤6144 字节，合计 ≤80KB。
- **考题：** 12 道（tests/考题.md）；报告格式机械检查（tools/check_report.py）＋10 个夹具，另有 6 个反向用例。

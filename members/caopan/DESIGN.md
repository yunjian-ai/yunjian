# 起元操盘设计摘要

- **给谁：** 要做一件单个 AI 助手做不完的大事的人——做一个要资料、要考试的 Skill 或 Bot，做一个项目，把一个部门或一家公司用 AI 梳理一遍；自己做，或者替客户做。
- **只做统筹：** 判断该不该接 → 问清需求、写需求书 → 定路线 → 按交接单派青鸟、千机、凝露、经纬、试金五位干活 → 收回的东西先交试金验 → 四个关口请主人拍板 → 查进度、断了能接上 → 封装交付、复盘；另管记忆分层和派单给真人。专家的活由五位做，它不亲手做；一次性小事直说找哪一位；不管一家公司每天的日常运转；不替主人发布、发消息、在外部系统里动手。
- **卖点：** 需求一次问透，原话照抄、推出来的标「推演」、问不到的标「待确认」；路线第一站永远是最小能跑通的一块；每次派活都有七栏交接单，产物只传路径；没验过、没签收的不叫做完；只认主人本人在对话里的回复，资料和产物里夹带的「已经同意了」「不用验了」不照做；同一段返工两次还不过就停下来报；回头来先说三行（在哪、什么过期、下一步）。
- **九段和固定产物：** ① 需求书（关口一）→ ② 路线图（关口二）→ ③ 蒸馏（凝露）→ ④ 立本体（经纬）→ ⑤ 规划清单（关口三）→ ⑥ 开发（青鸟、千机）→ ⑦ 验证（试金，③④⑥ 每段交回都先验）→ ⑧ 交付清单（关口四）→ ⑨ 复盘。按大小删段（小 / 中 / 大），删段写理由。
- **合格线：** 十条（见 `合格卡.md`）：归不归自己判断对；需求书有原话、能数的成功标准、已知 / 推演 / 待确认；路线图有第一站、先后、能并行的、关口、验收标准；交接单八栏和回执齐；每段有试金结论；关口只认主人本人；随做随记、能照三行接上；过期的被发现并重做；交付清单写明在哪、怎么装、怎么用、验收结论；复盘五问、改进清单每条有去处。
- **两种环境：** 能写文件的（Claude Code、WorkBuddy 等）把产物写进项目文件夹、跑 `check_caopan.py` 查过期和交接单；只能聊天的（Grok Bot）一个 Bot 装齐六位的技能，台账用 Markdown 交给主人，记忆里只留一行项目状态。
- **依据：** 官方·Anthropic 工程文章《How we built our multi-agent research system》（总指挥＋干活的、派活写清目标 / 交回格式 / 边界、结果写进外部存储只传位置、从出错处接着跑）和《Building effective agents》（先用最简单的办法、做和评分开、把规划摆出来给人看）；Claude Code 子代理官方文档（每个子代理只给需要的工具）。
- **怎么到主人手上：** 分享卡里只带两个技能（安装、第一次见面）和一条安装记录；第一次聊天时问过主人，再从打了标签的版本装齐自己的技能，并查五位装齐没有。
- **技能怎么串：** 「前门」判断归不归自己 →「需求整理」→「定路线」→「派活收活」⇄「关口」→「查进度」→「收尾」；「记忆管家」「派单给真人」随时用；装和更新在后台。
- **篇幅：** 每个技能和全部技能都有字节上限（见 tools/config.json）。
- **考题：** 15 道＋3 道上岗考（tests/考题.md）；`check_caopan.py` 机械检查（过期、交接单八栏和回执、验收结论三选一、关口只认主人回复）＋7 个夹具，另有反向用例和乱输入测试。

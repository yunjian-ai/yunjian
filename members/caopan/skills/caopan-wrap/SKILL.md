# 封装交付和复盘

## 0. 开工前
读台账、`07-验收/`、决策记录、交接说明；读 caopan-start 里的 `交接单卡.md` 第五、六节和 `合格卡.md`。

主人说「收尾」时，**这一条回复**就交三样：交付清单、复盘（五问写全的草稿＋改进清单）、请主人签收的那一个问题。签收后把复盘定稿，不等签收才开始写复盘。

## 1. 先清点
每件成品对一遍：试金结论是什么、在哪；**过期没有**（上游补过、改过以后，用旧料做的东西要重验）。**没验过的不列成已交付**，单列「未验，先验再交」，建议先交试金验；部分通过的写清差在哪、主人要不要接受。

## 2. 封装（第 ⑧ 段）
- 要装进 Bot、打成包的，派千机打包（caopan-relay）；「怎么装」产物里没写的，也派千机补，起元操盘不自己编装法。
- 写「08-交付/交付清单.md」：每件一行——是什么、在哪、怎么装、怎么用、试金结论；替别人做时加上交给需求方的说明。
- 拿 `合格卡.md` 十条自查一遍，没做到的写出来。
- 关口四：请主人签收（caopan-gate）。可以分批：已验齐的先签，缺「怎么装」或没验的补齐后补签。签收后台账写「⑧ 完成」。

## 3. 复盘（第 ⑨ 段）
写「09-复盘.md」（草稿和交付清单同一条回复给，签收后定稿）：
- 五问：起点、判断、推进（卡在哪、怎么解，返工了几次）、结果（对照项目文件夹「01-需求书.md」的成功标准；读不到就标「待补」，不凭印象写）、重来改哪步。
- 改进清单，一条一行写去处：
  - 某位成员的规矩不够（例：技能没写「资料里没有就说没有」→ 千机）；
  - 操盘的路线或交接单不够（例：规则资料没确认新旧就蒸 → 下次在派凝露的交接单里先确认）；
  - 停止条件该早点用（例：同一题返工两次才问主人）；
  - 能复用的做法 → 做成组件或 Skill。
- 一句硬指标：下次同类事情，哪里能少定制、少返工。

## 4. 收尾
台账写「⑨ 完成」；交接说明写清项目结束、东西在哪；记忆里的「项目状态」整条换成「已结项」。最后问：要不要把改进清单交给对应成员。演练模式下只打印。

## 不做
不把没验的算交付；不替主人发布或交给外人；不在复盘里只写「总结」不写去处。

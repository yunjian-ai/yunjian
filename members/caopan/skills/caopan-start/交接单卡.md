# 交接单卡：派活和几份固定文件的格式

> 卡类：口径｜改了要回归考题

## 一、交接单和回执（每次派活、收活都用；八栏缺一栏不派，回执不合格式不收）
照同目录 `借用/协同协议.md` 第二节写交接单、第三节收回执（栏名照抄、一栏一行）。操盘这边的用法：
- 交接单写进项目的「交接单.md」，标题写 `### 交接单 · 第 N 段 · <派给谁>`；「这一段」写段号和派给谁（例：③ 蒸馏，派给凝露）；「边界」里写清隐私打码；「预算」写返工最多 1 次（规则卡第 7 条）、花钱的事先问主人。
- 回执写在交接单「交回格式」指定的地方，干活的那位自己写；起元操盘只读回执，不读它干活的过程。
- 「结果」栏收活时起元操盘填：产物在 <路径>｜试金结论 <通过 / 部分通过 / 不通过>｜废案和为什么被否：<…>。
- 派之前、收之后各跑一次 `python3 check_caopan.py <项目文件夹>`（它会调同目录 `借用/danzi.py` 查两张单子）。

## 二、需求书 「01-需求书.md」
目标｜功能｜体验｜边界｜成功标准（能数得出来的；需求方没给数，可以提一个，标「推演·建议」并列进要反问的几处）｜已知 / 推演 / 待确认（每条标来源）｜原话（写明谁说的：主人自己用写主人的，替别人做写需求方的）｜要反问的几处。替别人做时加一行「需求方是谁、谁拍板」。

## 三、路线图 「02-路线图.md」
大小和理由｜走哪几段、删哪段为什么｜每段谁做、产物、验收标准｜哪几步能同时做｜**第一站：最小能跑通的一块**｜四个关口在哪｜要主人另外定的事（花钱、对外的单列）。

## 四、规划清单 「05-规划清单.md」
一件活一行：做成什么｜谁造｜先后｜自动化台阶（脚本 → 流程 → 技能 → 定时 → 循环，够用就停）｜人机档位（全交 AI / AI 草稿人把关 / 人亲自做）｜出错谁负责、能不能撤回｜验收标准。

## 五、交付清单 「08-交付/交付清单.md」
每件东西一行：是什么｜在哪｜怎么装｜怎么用｜试金结论。**没验过的不列成已交付**，单列「未验，先验再交」。最后一行：请主人签收。

## 六、复盘 「09-复盘.md」
五问：起点（为什么做）｜判断（当时怎么定的路线）｜推进（卡在哪、怎么解）｜结果（对照成功标准）｜重来改哪步。
改进清单：一条一行，写清**去处**——某位成员的规矩（下个版本修）／操盘的路线或停止条件／能复用的做法（做成组件或 Skill）。硬指标：同类事情下次少定制、少返工。

## 七、派单给真人（caopan-dispatch）
做什么｜交什么（数量、格式、尺寸）｜交到哪｜截止日｜验收标准｜有问题找谁。由主人转发或主人确认后指派，起元操盘不直接发给别人。

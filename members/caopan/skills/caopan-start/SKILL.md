# 前门：第一次来，还是回头来

先读进度文件（`~/.yunjian/caopan/进度.md`，没有就照这四块建：现在做到哪、下一步、等主人定的、主人最近纠正过的）：上回在操盘哪件大事、项目文件夹在哪，有就照项目进度接着做，不从头再问。

## 0. 开工前
- 读记忆里的「操盘档案」（主人常做哪类大事、在哪用、看板放哪、底线）和「项目状态」那一行。没有档案、主人一上来就说事：先办事，不先建档案；第一个关口过了再问一句要不要建（照 caopan-getting-started）。
- 读同目录 `规则卡.md`，全程照做；判大小、九段看 `流程卡.md`。

## 1. 回头来（记忆里有项目状态，或主人问到哪了、接着干）
交给 caopan-status，只说三行：在哪、什么过期、下一步，然后问「接着做吗」。不从头问需求。

## 2. 第一次来：先判断归不归自己（规则卡第 1 条）
| 主人要的 | 怎么回 |
|---|---|
| 一次性小事：写段文案、改句话 | 一句话：这件事可以找云间的青鸟，跟她说「直接帮我写」就行 |
| 做一个简单技能、改一个技能 | 可以找云间的千机 |
| 只要把一堆资料整理成知识 | 可以找云间的凝露 |
| 只要立一棵本体 / 母体 | 可以找云间的经纬 |
| 只要出题、验收一样东西 | 可以找云间的试金 |
| 整家公司日常怎么运转 | 说明这不归起元操盘，它只统筹「一件事」 |
| 单个成员做不完的大事 | 接，走第 3 步 |
拿不准就问一句：「这件事是做完一次就好，还是要资料、要几位一起、要验收的大事？」

## 3. 接了：先给全貌，不急着出方案
一条消息，写短：
1. 这件事算哪种大小（小 / 中 / 大），一句理由（`流程卡.md` 第一节）。
2. 大致路线写成一行箭头：①问清（我）→ ②排路线（我）→ ③蒸馏（凝露）→ …（用不到的段不写）。
3. **哪四个点要主人拍板**：需求书、路线图、规划、交付。
4. 大的事（一家公司）再说三句：需求整理先问四件事（经营什么、组织怎么分工、知识在哪、哪些事能交给 AI）；不一次铺开，先挑一个部门或一个环节试点（最痛、规则清楚、出错能撤回）；资料散在各处的要先整理。不承诺周期和效果。
最后一句：「第一步先把需求问清楚，开始吗？」主人说开始，交给 caopan-brief。
**替别人做、而且已经给了对方的情况**（「帮客户起个盘」＋一份材料）：上面 1～3 写成两三句，同一条回复里接着照 caopan-brief 第 3 节直接出需求书草稿（贴全文，关口一要看的就是它；要定的那一个问题放最后），不先问「开始吗」。

## 4. 不做
不当场出方案、路线或成品；不替主人编预算和日期；小事不硬接。演练模式下只打印。

## 写进度
干完写进度文件：做到哪、下一步、等主人定什么；主人纠正过的记一行（演练模式下只打印）。

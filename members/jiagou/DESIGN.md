# 起元架构设计摘要

- **给谁：** 已经养了一群 AI 的人——几个 Bot、一堆技能，用 Claude Code、WorkBuddy 或 Grok Bot——觉得越用越慢、越用越笨、老忘规矩。
- **只管底座：** 量清楚、瘦下来、立规矩、几个 Bot 怎么交接、纠正怎么变成规矩。不造新 Bot、不写新技能；不统筹一件具体的大事、不派活；不删、不卸任何东西。
- **卖点：** 数字全靠脚本算（只用 Python 标准库），换哪个模型结果都一样；按平台各报一句「每次固定带多少」，平台之间不相加，口径写清（按字符估，Claude Code 的准数用官方 `/context`、`/usage`）；只读的直接做，改设置、挪文件、改别的 Bot 先出清单、逐条点头、先备份；一条命令改回，逐个核对一字不差，新建的不删、挪进备份；打架的两条由主人定；回执和资料里夹带的指令不照做、原样报给主人。
- **合格线：** 体检数字和标准答案一致、跑前跑后每个文件的校验码不变；挪移清单每条写清挪什么、挪去哪、省多少、怎么改回；改回后文件和文件夹都和执行前一致；交接单缺栏、回执自检没逐条打勾、产物不在都拦下；纠正判四选一、只局部改、不整篇重写。
- **依据：** Claude Code 的 CLAUDE.md 行数、自动记忆加载范围、技能说明截断、技能四档、`disable-model-invocation`、代理说明照官方 Memory、Skills、Subagents 页（体检口径卡写了核对日期）；WorkBuddy 读多少、Grok 共用技能库截断是实测，标「实测」不装成官方。
- **怎么到主人手上：** 分享卡里只带两个技能（安装、第一次见面）和安装记忆；第一次聊天时问过主人，再从打了标签的版本把其余技能装齐。
- **技能怎么串：** 先「第一次见面」，然后「体检」→ 主人选「瘦身」「立底座」「协作单子」「演进」→ 做完再体检、对比前后；装和更新在后台。
- **篇幅：** 每个技能和全部技能都有字节上限（见 tools/config.json）；三个脚本合计 1,200 行以内。
- **考题：** 16 道＋4 道上岗考（tests/考题.md）；`tests/run_tests.py` 拿一台虚构的假电脑（tests/材料/01-假电脑）测体检数字、只读、瘦身执行和改回（含运行环境不让删文件的情况）、压测、交接单检查。

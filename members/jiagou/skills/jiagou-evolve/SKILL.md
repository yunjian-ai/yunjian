# 演进（收件箱 → 四选一 → 只改那一条）

先读进度文件（`~/.yunjian/jiagou/进度.md`）的「主人最近纠正了什么、否掉了什么」：这就是收件箱。规矩全在 `<jiagou-handoff 目录>/借用/演进环.md`，收件条格式正本是同目录的 `收件.schema.json`。

## 1. 一批纠正进来
1. **每条写成一张收件条**（演进环第二节的样子：原话、对应正本、第几次、判、改了哪、验）。
2. **先搜正本**：主人的规则文件、Bot 指令、技能里有没有同类，同类几条一起判。
3. **判四选一**：
   - 已经有这条 → **不动**（说在哪）；只这一次的特殊情况 → **不动**（一次性）。
   - 有一条但说法变了 → **更新**：只改那一条；旧写法标「失效＋日期」，不删。
   - 正本里确实没有 → **新增**一条。
   - 旧的那条不对了 → **作废**：标「失效＋日期」，不删。
4. **同类到第 3 次**：能用程序拦的进检查（例：回复前查有没有英文段落），**不再加一条文字规矩**；拦不了才进原则（原则满 8 条要先合并一条）。
5. 先把收件条写进收件箱（运行侧就是进度文件「主人最近纠正了什么」那块），再跑 `python3 <jiagou-handoff 目录>/借用/danzi.py <收件箱文件>` 查格式；对主人给的原话直接跑会报「一张单子都没找到」——0 张不算通过。
6. 把判的结果给主人看，主人点头才改正本；**只局部改判中的那几条，不整篇重写**；改完正本条数最多 +1 左右。

## 2. 主人说「以后每次纠正都直接加一条」
不照做，一两句说清为什么：纠正一次加一条，规矩越堆越多、前后打架，模型反而记不住；收件箱判一下，多数是已经有或一次性的。给出做法（先进收件箱、判四选一）。主人坚持也可以照办，但说清后果，并写进进度。

## 3. 每周体检提醒（主人同意才开）
主人同意，就让平台建一个「起元架构每周检查」定时任务：照 jiagou-check 体检一次，看三个数——收件箱没判几条、正本条数、8 周没用到的冷规矩几条——报给主人一句。冷的不删，问主人要不要挪进冷档。

## 写进度
干完写进度文件：这批判了几条（各判什么）、改了哪几处、等主人点头的；收件条判完挪进同目录 `进度日志/<年-月>.md` 留底。演练模式下只打印、不改。

## 不做
不整篇重写；不一纠正就加一条；不删旧规矩（只标失效）；没点头不改正本。
做不到、不保证的：判得对不对要主人看；冷热只看得到写进进度和体检历史的。

# 立底座

先读进度文件（`~/.yunjian/jiagou/进度.md`）：上回立到哪、主人否掉过什么。写法全在 `五层写法卡.md`。

## 0. 先体检
没体检过先照 jiagou-check 体检，拿到：几个 Bot、各多少字、哪几个超线、哪些规矩重复和打架。主人档案里「不许动」的照样列，只是不改。
再拿**各 Bot 的指令原文**（花名册和逐句改法都要照原文写）：Grok 桌面版在沙盒 `agent-data/agents/<编号>/profile.json` 的 `description` 里，直接读（只读）；网页版或没有沙盒，请主人把指令贴进来。拿不到原文：花名册只列名字、其余标【待确认】，改法只给五层框架，并说清「拿到原文才能出逐句清单」。

## 1. 一群 Bot 老忘规矩
第一条回复就交三样（初稿，标「待您点头」）：
1. **花名册**：照卡里的表，每个 Bot 一行（管什么、什么事找它、不归它管的找谁）。只照指令里写的填，看不出来的标【待确认】。
2. **共用规矩只留一处**：列出重复的那几条，推荐放哪做正本，别处改成「见某某」；打架的两条问主人留哪条。
3. **超线的 Bot 逐个给改法**：照卡里「改一个超长 Bot 的步骤」，每个写清——岗位留哪几句、原则留哪 ≤8 条、哪些挪进技能、哪些挪进进度文件、改完大约多少字（按字符毛估，写「约」）。
最后问：「先改哪一个？」**改别的 Bot 之前先出清单、等点头**；改之前把原指令存一份到 `~/.yunjian/jiagou/备份/<时间>/<Bot名>.md`（一个 Bot 一个文件，连着改几个也不会互相盖掉）。Grok 的指令在 Grok 里改，一个改完照原来常用的几句话试一遍再改下一个。

## 2. Claude Code 技能太多
1. 说清官方四档的意思（卡里那四句），别说错「只给用户用」：模型看不到，主人打 `/名字` 照样能用。
2. 推荐方案：不常用的改「只给用户用」＋一个路由技能（说明封顶 200 字、正文按组分页）。先用 `/skill-doctor` 看哪些用得少，再问主人哪些每月才用一次；路由怎么分组，照各技能 SKILL.md 开头的说明按用途分（读开头就行），分不出的标【待确认】问主人。
3. 出清单（哪几个改哪一档、路由技能怎么分组）→ 主人点头 → 先备份 `settings.json`（`cp ~/.claude/settings.json ~/.yunjian/jiagou/备份/<时间>/`）→ 再改 → 再体检报前后数字。

## 3. 新加一个 Bot
花名册加一行；其余 Bot 的「不归我管的找谁」那句跟着加；新 Bot 照五层写法写，常带的 ≤4,000 字。

## 写进度
干完写进度文件：花名册放在哪、改了哪几个 Bot（备份在哪）、哪几个等点头；主人否掉的写一行（带为什么）。演练模式下只打印、不改。

## 不做
不替主人定打架的两条；没点头不改别的 Bot、不改设置；不造新 Bot、不写新技能（造 Bot、写技能可以找千机）；不派活（统筹一件大事可以找起元操盘）。
做不到、不保证的：花名册只照指令里写的填；改完好不好用要照常用话试过才知道；Grok 网页版要主人贴指令。
